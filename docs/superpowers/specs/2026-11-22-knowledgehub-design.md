# KnowledgeHub 首版设计

## 目标与范围

KnowledgeHub 是用 Docker 部署的个人知识库应用。普通用户从登录页自行注册，注册后即可登录。每位普通用户可以创建和切换多个私有知识库，用嵌套文件夹组织 Markdown 笔记，在线编辑和手动保存，也可以搜索笔记标题和正文。管理员负责账号停用与恢复，账号管理权限不包含读取知识库内容。

首版上传支持 `.md` 导入和笔记内图片。用户可以将整个非空知识库移入知识库回收站并恢复，也可以从各库的内容回收站恢复笔记和整个文件夹。两类回收站都保留条目，直到用户恢复或确认永久删除。服务部署在单台机器，供本机或局域网访问。首版范围止于个人知识库，不包含分享、协作、多媒体附件、ZIP 批量导入和公网部署。

领域术语以 [CONTEXT.md](../../../CONTEXT.md) 为准。

## 存储方案

用户已选择 PostgreSQL 存储 Markdown 正文，FastDFS 存储笔记图片。导入时读取 Markdown 文本生成笔记。保存后搜索直接读取最新正文，目录、正文、图片引用记录和回收状态可由数据库事务协调。FastDFS 管理图片文件，PostgreSQL 保存图片归属和存储标识。

备选方案将 Markdown 正文和图片都作为 FastDFS 文件，PostgreSQL 保留目录和搜索数据。该方案需要在每次编辑后协调文件写入和搜索数据更新，并处理一边成功一边失败时的重试。首版选择前一方案，以简化正文编辑和搜索的一致性。详见 [存储决策](../../adr/0001-store-markdown-in-postgresql.md)。

## 应用与账号权限

- Vue 3、TypeScript 和 Element Plus 提供登录注册、知识库操作和账号管理。Spring Boot 暴露同源 REST API，PostgreSQL 存储应用数据，FastDFS 仅接受内部文件请求。
- 自助注册只创建普通用户账号。设计默认注册时同时初始化一个可重命名的默认知识库，之后用户可以创建其他知识库。设计默认用唯一用户名和密码登录，密码使用 Spring Security 支持的自适应哈希保存。注册和登录限速，首个管理员通过部署配置初始化一次，应用重启时保留原有管理员凭据。
- 普通用户可以操作自己拥有的知识库及其文件夹、笔记、图片和内容回收站，也可以管理账号下的知识库回收站。管理员可以列出普通用户账号、查看账号状态、停用和恢复账号。匿名用户只可使用登录、注册所需的公开入口。服务器从会话确定账号，校验所选知识库及资源的归属。越权读取的响应不泄露资源是否存在。
- 使用服务端会话和 `HttpOnly` 会话 Cookie，对修改状态的请求校验 CSRF，包括上传。每次访问受保护资源时校验账号状态和会话版本。管理员确认停用后，用户后续请求失效，恢复也不重新启用旧会话。用户应重新登录才能访问原知识库。[Spring Security 会话](https://docs.spring.io/spring-security/reference/servlet/authentication/session-management.html) · [CSRF](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html)

## 笔记、文件夹与搜索

- 用户可创建、重命名和切换自己的知识库。同一用户的活动知识库名称唯一。用户没有活动知识库时，工作台提供创建知识库入口，账号下的知识库回收站仍可访问。
- 每个知识库有自己的根目录。用户可在该库的根目录或任意文件夹新建、导入和移动笔记，也可创建、重命名和移动文件夹。同一父目录下活动文件夹的名称唯一，笔记可同名。移动文件夹时禁止移入自身或后代。设计默认首版的移动操作在同一个知识库内完成。移动和删除的校验与写入在同一事务中完成。
- 上传单个 UTF-8 `.md` 文件时，将文件名去掉扩展名作为初始标题，正文直接保存到当前目录的一篇新笔记中。保留原有 Markdown 语法与相对图片引用，预览提示未能加载的本地图片，用户可以在编辑器中上传图片并替换原有引用。
- 用户可在线编辑标题和 Markdown 正文，用预览检查排版。点击「保存」才更新笔记，离开有未保存修改的页面时提醒。保存请求携带读取时的笔记版本。两个标签页先后保存同一篇笔记时，过期版本得到冲突提示，编辑中的内容留在页面上供用户处理。
- 搜索以用户输入的字面关键词匹配当前选中库的活动笔记标题或已保存的 Markdown 正文，支持中文连续子串和英文大小写不敏感匹配。结果分页返回标题、所在路径和更新时间。首版直接用 PostgreSQL 查询，是否加索引由代表性数据的查询表现决定。[PostgreSQL 模式匹配](https://www.postgresql.org/docs/18/functions-matching.html)

## 图片、回收与永久删除

- 编辑器上传图片后插入 Markdown 图片语法，引用同源图片地址。服务器校验上传的实际文件类型和大小，通过 FastDFS 写入二进制，在 PostgreSQL 记录图片所有者、应用图片 ID 和存储标识。应用图片 ID 用于 Markdown 引用，FastDFS 地址不进入用户文档。设计默认允许 PNG、JPEG、GIF 和 WebP，单张图片上限 10 MiB，单个 Markdown 文件上限 2 MiB。
- 浏览器通过应用接口读取图片，服务端每次检查账号和知识库归属，私有图片响应禁止缓存。预览过滤原始 HTML 和不安全 URL，仅加载同源的应用图片，外链图片保留原语法并显示占位。保存时拒绝引用其他知识库的应用图片。同一知识库的多篇笔记可以复用同一图片。
- 保存笔记时，正文和图片引用关系在同一事务内更新。首次上传的图片在笔记保存前暂存，默认保留 24 小时供编辑使用。用户保存时若暂存图片已过期，提示重新上传并保留未保存正文。后台清理只处理过期且无引用的暂存图片，或曾被正文引用、后来确认无引用的图片。活动笔记与回收站笔记的引用都需要保留图片。
- 每个知识库有独立的内容回收站。删除笔记或文件夹会生成所属知识库的回收记录。非空文件夹进入内容回收站时，其下仍处于活动状态的文件夹和笔记一起移入同一回收记录。更早独立移入的内容保留原回收记录。回收条目不参与普通浏览和搜索。
- 恢复库内条目时优先返回原位置。原父目录不可用时恢复到根目录，文件夹同名冲突时为恢复项分配可辨识的后缀，保持子树结构。用户确认永久删除后，应用在数据库事务内移除该回收记录包含的条目和图片引用。若其他回收记录的原父目录因此消失，这些记录继续保留，之后恢复到根目录。
- 用户可以在账号下的知识库回收站找回整个知识库。移入时只改变该知识库的状态，停止普通浏览、搜索、编辑和图片读取，保留库内资源和已有内容回收记录。恢复后，原有活动内容重新可用，原来在内容回收站里的条目仍保持原状态。若已有同名活动知识库，为恢复项分配可辨识的后缀。
- 用户确认永久删除一个知识库后，应用移除该库的全部内容和回收记录，并把待删图片交给后台队列。永久删除笔记或文件夹时，只有无其他引用的图片才进入队列。队列用于处理 FastDFS 删除失败后的重试，队列记录独立于已删除的知识库，保存与清理通过图片状态互斥。
- 上传失败时不返回有效图片地址。若已拿到 FastDFS 标识但图片记录无法提交，尝试补偿删除，并记录补偿失败的对象以便维护处理。FastDFS 调用超时且没有返回文件标识时，应用无法定点删除该次写入可能遗留的文件，需要记录调用异常并在运维检查中核对存储。普通的笔记编辑和保存不依赖 FastDFS 在线。

## 数据与接口边界

核心数据包括账号、个人知识库和其回收状态、文件夹、笔记、图片、笔记图片引用、库内回收记录和图片清理任务。数据库迁移由 Flyway 管理。每个知识库关联一位所有者，同一个所有者可以关联多个知识库。所有相关资源保留所属知识库标识，通过关联约束保护同一知识库内的目录、笔记与图片关系。校验库状态与执行写入在同一事务内完成，树修改、内容回收和整库回收需要协调相关写入，避免并发移动造成循环，以及在整库回收过程中产生半可见子树。

API 按认证、账号管理、知识库、文件夹、笔记、图片和回收站组织。普通用户发起资源操作时指明目标知识库，由服务端验证该知识库和资源都属于当前用户。账号管理接口使用独立的管理员角色检查。文件导入和图片上传采用 multipart，请求和响应字段由实施计划细化。冲突和校验失败返回可辨识的错误，前端保留用户未保存的输入。

## Docker 部署

Docker Compose 启动前端静态服务及反向代理、Spring Boot、PostgreSQL、FastDFS Tracker 和 Storage。对宿主机只发布 Web 入口。默认绑定 `127.0.0.1`，局域网模式由部署者指定监听地址。明文 HTTP 适用于本机验证，局域网可配置启用 HTTPS 并发送 `Secure` 会话 Cookie。应用数据和 FastDFS 存储使用持久化卷，配置示例与实际凭据分开管理。

为 PostgreSQL 和 FastDFS 设置可用性检查，启动验收须验证 Tracker 返回的 Storage 地址可以从 Spring Boot 容器实际访问。交付提供 Compose 启动与初始化步骤，以及在暂停应用写入时一起备份和恢复 PostgreSQL 与 FastDFS 数据的说明。[Docker Compose 启动顺序](https://docs.docker.com/compose/how-tos/startup-order/) · [FastDFS 项目文档](https://github.com/happyfish100/fastdfs)

## 验收场景

1. 注册两个普通用户，注册成功后直接登录。让其中一人在两个知识库分别建立目录、导入同名 Markdown 和上传图片，切换知识库时浏览和搜索只显示该库的内容。验证对方的知识库、笔记、图片、搜索结果和回收条目均无法读取，管理员也不能打开这些内容。
2. 在嵌套目录导入含相对图片引用的 `.md`，打开生成的笔记，手动补传图片并保存。验证标题和中文正文均可搜索，重新加载后图片可见。取消有修改的编辑时显示提醒，两处同时编辑时旧版本不会悄悄覆盖新内容。
3. 移动和重命名文件夹，拒绝移动到后代。删除非空文件夹后从浏览和搜索隐藏，恢复时连同随它删除的子项与图片一起回来。先单独删除一篇笔记，再永久删除它原来的文件夹，验证该笔记仍可恢复到根目录。另有笔记引用的图片继续可用。
4. 把有正常笔记、图片和库内回收条目的知识库移入知识库回收站。验证从活动库列表和搜索隐藏，旧笔记和图片地址不可访问，其他知识库照常使用。恢复后验证笔记、图片和原来的内容回收站状态正确。再次移入并确认永久删除后无法恢复。
5. 管理员停用一个在线用户，验证原会话的读取、保存和图片请求均被拒绝。恢复账号后验证旧会话仍失效，并确认重新登录可使用原知识库。
6. 用 Docker Compose 从空数据卷启动项目，在浏览器走完注册、导入、保存、图片上传和搜索，重启服务后验证账号、笔记和图片仍保留。用独立数据卷验证备份可以同时恢复正文和图片。

## 实施时细化

前端编辑器库、组件交互、依赖版本、数据表字段、REST 路由、索引和具体容器镜像由实施阶段选择。首版用户名密码登录、初始化默认知识库、库内移动、上传限额、暂存时间、外链图片占位、同名恢复规则和局域网监听方式均为设计默认值，可在设计评审时修改。
